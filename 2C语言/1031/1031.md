文件类型

- `l`   link 快捷方式,链接文件
- `s`   套接字文件                            
- `c`   字符设备文件                          如串行设备、音频设备、键盘、鼠标
- `b`   块设备文件                            如硬盘、U盘等存储设备

权限
- `r`   read
- `w`   write
- `x`   execute
- `-`   没有权限

用户
- `u`   user    用户
- `g`   group   同组
- `o`   other   其他
- `a`   all     所有

命令
- `chmod`   修改权限
- `chown`   修改所有者
- `chgrp`   修正组

1. 对称加密算法
   加密和解密使用同一个密钥，速度快，适合加密大量数据
   -DES：数据加密标准，使用56位密钥，由于安全性不足已被淘汰
   -3DES：基于DES，使用三个不同的密钥进行三次加密，安全性更高但速度较慢
   -AES：高级加密标准，支持128、192、256位密钥长度，目前最广泛使用的对称加密算法
   非对称加密算法
   使用公钥和私钥对，公钥可以公开，私钥保密，安全性更高但速度较慢
   -RSA：目前应用最广泛的非对称加密算法，基于大整数因子分解难题
   -ECC：椭圆曲线加密算法，密钥长度较短但安全性高，适合移动设备等资源有限的场景
   -DSA：数字签名算法，主要用于数字签名场景
   哈希算法
   不可逆加密，将任意长度数据转换为固定长度的哈希值，主要用于验证数据完整性
   -MD5：生成128位哈希值，虽然速度快但已被破解，不建议用于安全敏感场景
   -SHA-1：生成160位哈希值，比MD5更安全但逐渐被取代
   -SHA-256：SHA-2系列算法，生成256位哈希值，目前最推荐的哈希算法

2. SHA256加盐是一种密码学技术，通过在原始数据（如密码）中添加随机字符串（盐），再进行SHA256哈希运算，显著提升数据存储的安全性

3. 连接发起与版本协商：客户端向服务端发起SSH连接请求，服务端响应并交换协议版本信息，确保双方使用兼容的SSH协议。
   密钥交换与加密通道建立：服务端发送公钥、随机数等信息，客户端生成会话密钥（Session Key）并用公钥加密后传输，双方通过加密算法建立安全通信通道。
   身份认证：支持密码认证或公钥认证。密码认证需输入账号密码；公钥认证需提前将本地公钥上传至服务端authorized_keys文件，通过私钥加密随机字符串完成验证12。
   会话创建与命令执行：认证成功后，服务端创建新会话，客户端可发送加密命令，服务端执行后返回结果，实现远程操作
   配置要点：
   服务端准备：确保SSH服务已安装并启动（如OpenSSH服务器），检查sshd进程状态。
   客户端连接：使用ssh username@host命令连接，默认端口22，首次连接需接受主机指纹。
   免密登录设置：通过ssh-keygen -t rsa -b 4096生成密钥对，将公钥内容添加至服务端～/.ssh/authorized_keys文件
