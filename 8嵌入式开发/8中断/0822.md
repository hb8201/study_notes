# 中断

在主程序运行过程中，出现了特定的中断触发条件（中断源），使得CPU暂停当前正在运行的程序，转而去处理中断程序，处理完成后又返回原来被暂停的位置继续运行

## 过程
- 中断源触发中断
- CPU响应中断
    - 保护现场：当前程序执行的位置（返回地址，PC），当前的程序状态（CPSR），当前的数据（压栈）
    - 中断响应：将中断处理函数的入口地址赋值给PC，执行中断服务程序
    - 恢复现场：弹栈
    

## 中断服务

中断服务函数的名称在系统启动程序的中断向量表中定义，中断服务程序的实现一般在stm32f10x_it.c中实现（stm32f10x_it.h说明原型）

中断服务程序没有返回值，中断服务的处理流程一般都很简单

## 优先级中断
抢占优先级的级别高于响应优先级
抢占优先级高的可以打断抢占优先级低的中断，如果抢占优先级相同，响应优先级高的不能打断低的

## 中断和函数的区别
- 函数调用：是你自己看手表，计划好“3分钟后我去下楼拿快递”。
- 中断：是你在家看电视，突然门铃响了（外部事件），你必须立刻把遥控器放好（保存现场）去开门，开完门回来拿起遥控器继续看（恢复现场），至于门铃什么时候响，你完全预测不了。

## 外部中断

操作流程
- 初始化IO口为输入
- 开启IO复用时钟        APB2ENR的bit0置位
- 开启与该IO口相对的线上中断/事件，设置触发条件(建议不配置EMR)
- 配置中断分组（NVIC），并使能中断
```c
// miss.h中定义了
typedef struct
{
  uint8_t NVIC_IRQChannel;                      // 中断通道，中断源
  uint8_t NVIC_IRQChannelPreemptionPriority;    // 抢占优先级
  uint8_t NVIC_IRQChannelSubPriority;           // 响应优先级
  FunctionalState NVIC_IRQChannelCmd;           // 中断使能或失能
} NVIC_InitTypeDef;
```
- 编写中断服务函数（中断发送以后，自动调用的处理，CPU自动响应）



## 总结
- 配置中断源使用的GPIO引脚，开启端口的时钟和复用时钟，将端口设为上拉输入
- 配置NVIC，配置中断优先级中断分组，配置中断通道，配置响应优先级、抢占优先级，只能中断通道
- 配置EXTI，配置中断线，中断线和某个引脚关联，设置中断模式、触发方式，使能中断
- 配置中断处理函数
