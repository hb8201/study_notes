- arch: 根据CPU体系结构的不同而区分的代码
- crypto: 加密、压缩、CRC校验算法
- Document: 内核文档
- dirver: 驱动设备程序源代码。定制的驱动设备可以放到改目录的特定的分类中，随操作系统一起编译
- fs: 与文件系统有关的源代码
- include: 内核所需要的头文件。实现驱动程序时使用的就是该路径下的头文件（不是c库中的），和平台无关的头文件在include/linux目录
- kernel: Linux内核核心部分代码（完成操作系统核心功能部分代码）
- lib: 库文件相关代码（与平台有关）
- mm: 实现内存管理的源代码，和硬件系统架构无关的部分（相关部分在arch文件）
- net: 网络协议栈
- scripts: 配置内核的脚本
- usr: 与用户相关的文件 gen_init_cpio.c是cpio命名的实现（制作根文件系统的命名 - 将根文件和内核组织在一起）




Linux内核配置和编译：
为了简化内核源代码的编译，采用以下机制：
- Makefike：根据配置情况，构造出需要编译的源文件列表，然后分别编译，并将目标代码链接到一起，最终形成linux内核的二进制文件
- Kconfig：为用户提供的层次化的配置选项文件。执行make menuconfig的时候会通过分布在各个子目录的Kconfig文件在构建用户界面
- .config：内核配置的结果，用户配置完成以后会将所有的配置信息保存到该文件中

make mrproper   清除目标文件、中间依赖文件 + 核心配置文件

## Linux 内核模块（LKM - Loadable Kernel Module）的编译、加载与调试流程

```c
// TextDriver0818.md
// 简单驱动设备
#include <linux/init.h>
#include <linux/fs.h>
#include <linux/types.h>
#include <linux/kernel.h>
#include <linux/module.h>

MODULE_LICENSE("Dual BSD/GPL");

// 设备初始化：完成硬件设备初始化，并向操作系统注册该设备
static int test_init(void )
{
    // 设备硬件初始化

    // 设备注册

    // 输出的信息具有日志级别
    printk(KERN_ALERT"hello, my first driver login\n"); // 从内核中输出的函数
    return 0;
}

// 设备的注销：是否设备所占用的资源，从操作系统注销给该设备
static void text_exit(void)
{
    // 设备所占资源释放

    // 设备注销

    // 输出的信息具有日志级别
    printk(KERN_ALERT"bye, my first driver exit\n"); // 从内核中输出的函数
}

module_init(test_init);
module_exit(text_exit);
```

```
obj-m := TextDriver0818.o

PWD := $(shell pwd)

```

- make                              编译生成的 TextDriver0818.ko 就是驱动程序
